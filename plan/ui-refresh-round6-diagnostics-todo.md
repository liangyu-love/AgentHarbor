# Round 6 — 路由诊断、能力目录重做与清空路由记录

## 用户诉求
- 「请求级路由诊断」「模型能力目录与匹配预览」两块 UI 优化。
- 路由记录目前无法清空 → 增加清空。
- 做完一起本地提交并打包。

## 现状
- 路由记录是进程内环形缓冲（`route_trace`，最多 60 条，重启即清空），没有清空入口。
- 诊断头部把「开关按钮」和「联网搜索 / 全局压缩」两个全局设置挤在一行；展开后每条记录是长段落堆叠。
- 能力目录每个模型展开后是 7+ 个同样的框，信息层级不清。
- 测试约束：两个 section 的 aria-label 与同名切换按钮、`summary` 结构、`details` 用卡片底色（壁纸透明度测试）、
  若干文本格式（"尝试 ID: xxx"、"成员 ID: xxx"、"配置 / 执行协议: a → b"、"2.5 / 10"、"倍率 ×0.5" 等）。

## 步骤
1. [x] 后端：`route_trace::clear()` 只清已结束的记录（进行中的保留，避免正在跑的请求消失），返回清掉的条数；
       命令 `clear_route_diagnostics`；纯函数单测。
2. [x] 路由诊断重做：头部 = 切换按钮 + 条数/实时标记 + 设置胶囊（联网搜索、全局压缩）；
       展开后统计条（请求数、失败、平均耗时、首字中位数）、来源筛选、仅看失败、刷新、清空；
       每条记录一行摘要（状态点、模型链、来源、尝试次数、HTTP、耗时条、时间），展开为尝试时间线 + 事实网格。
3. [x] 能力目录重做：目录状态条（来源/规模/版本/时间 + 刷新）、搜索 + 带计数的筛选分段；
       摘要行加中转色块与上下文/输出/价格速览；展开为规格四格 + 压缩/匹配/冲突 + 匹配过程/目录身份 + 清除控件。
4. [x] 文案 zh/en、fixture 支持清空、回归测试补断言。
5. [x] 构建、Rust/前端回归、截图核对；本地提交并打包。

## 结果
- 后端 `route_trace::clear()` + 命令 `clear_route_diagnostics`：只清已结束的记录，进行中的保留；单测覆盖。
- 路由诊断：头部为切换按钮 + 实时条数 + 设置胶囊（联网搜索 / 全局压缩）；展开后统计（请求、失败、平均耗时、首字中位数，≥1s 显示秒）、
  来源筛选、仅看失败、刷新、清空记录；每条一行摘要（状态点、模型链、来源、尝试次数、HTTP、相对耗时条、时间），
  展开为尝试时间线（失败红点 / 成功绿点）+ 两列事实 + 标签 + 发送参数。
- 能力目录：目录状态条内置刷新；搜索 + 带计数的筛选分段；摘要行加中转色块与上下文/输出/价格速览；
  展开后规格四格用展示字体数值，其余面板统一为 `cap-panel`。
- 测试：`test-aggregation-board.mjs` 新增诊断统计 / 仅看失败 / 清空保留进行中请求；magpie、capability-clear、price-cache 范围全过。
