# Pi 模型接入

在「中转注入」页顶部点击 Pi 图标，会展开客户端配置并定位到 Pi 的配置按钮。

## 使用

1. 在「中转模型」页配置中转卡片和模型的协议、上下文、输出上限等。
2. 打开 Pi 配置，选择「直连接入」或「本地路由」。可同时选择多张卡片，并勾选每张卡片的模型。
3. 路由模式还能加入模型聚合，选择聚合入口协议。生成的 Pi 配置使用聚合公共模型 ID，不固定某个成员。
4. 先预览，再应用。预览隐藏凭据。保存后的配置可以重新应用，也可以恢复应用前的配置。
5. 在 Pi 中打开 `/model` 刷新并选择模型。Pi 的默认模型继续由 Pi 自己管理；界面中的「配置基准模型」仅用于选定要覆盖上下文/输出上限的那一项。

默认文件为 `~/.pi/agent/models.json`。设置了 `PI_CODING_AGENT_DIR` 时使用该目录（支持 `~`）；隔离测试根优先于真实目录。未安装 Pi 也可以准备配置，应用不会代为安装 CLI。

## 配置和协议

每张中转按实际协议分组，生成稳定标识 `agentharbor-relay-<卡片ID>-<api>`。聚合供应商使用 `agentharbor-aggregation-<api>`。它们与 Pi 官方供应商的登录记录独立，原有供应商保持可用。

| 出口 | Pi api | SDK 根地址 |
| --- | --- | --- |
| Chat Completions | `openai-completions` | OpenAI 根的 `/v1` |
| Responses | `openai-responses` | OpenAI 根的 `/v1` |
| Anthropic Messages | `anthropic-messages` | Messages 根，不重复加 `/v1` |

实际地址沿用现有官方提供商与中转地址解析。直连使用中转凭据；路由使用本地网关凭据和 `/clients/pi/p/<卡片ID>`，聚合使用 `/clients/pi/aggregate`。Messages 需要 Bearer 时生成 `authHeader: true`。Pi SDK 也可能同时带同值的 `x-api-key`；本地网关按自己的 Bearer 校验。原始模型 ID 保持不变，不使用 Codex 的 `卡片ID::模型` 格式。

上下文、输出、推理能力沿用路由的统一解析结果（手动覆盖、上游、目录及公共默认值）。未知输出沿用公共 8192 默认值；仅当投影未提供任何输出上限时才使用 Pi 的 16384 默认，并限制在上下文以内。Pi 可选的思考档位来自已声明档位，不凭名称添加 `xhigh` 等档位。图像输入只在完整能力匹配明确声明时开放，Fast 的上下文参考不会附带视觉能力。

静态美元价格复用现有价格解析、自定义价格与倍率。条件价格和聚合的动态成员价格无法用 Pi 固定 cost 表示时不填；Pi 对缺失单价显示的默认零值不代表渠道免费，实际费用和缓存用量仍以 AgentHarbor 账本为准。

## 保存与恢复

复用客户端配置管理的字段归属、加密恢复记录、版本校验与原子写入。仅接管生成的供应商字段，其他供应商和未受管字段保留。受管模型数组有外部改动时，通过现有冲突流程处理；首次遇到外部同名供应商时拒绝覆盖。没有修改时，恢复可以保留原文件的注释与原始字节。

密钥写入前按 Pi 的字面量规则转义 `$` 和开头的 `!`。外部供应商中原有的环境变量、命令表达式保留，AgentHarbor 不执行它们。`auth.json` 和 `settings.json` 不在管理范围内。

Pi 路由配置独立保持本地网关运行，关闭 Codex 路由不影响它。正常退出应用会按既有机制尝试撤回各客户端路由配置。直连配置持久保留。强制结束进程仍会让本地地址不可用。
