# 自动值恢复与 Codex 压缩阈值

2026-10-08

## 使用方式

模型能力目录里的“恢复自动值”用于移除已经保存的手动设置。填写新数值、选择 `272K` 或修改压缩策略，仍在中转模型编辑中完成。

- 没有手动设置的模型不显示恢复操作。
- 下拉列表只列出实际保存的模型设置和中转设置；中转设置即使被模型设置遮住，也仍可移除。
- “预览恢复结果”展示当前值、恢复后的值及来源，再点击“确认恢复自动值”保存。
- 自动来源可能是上级设置、上游声明、官方目录或 models.dev；不保证总是回到 models.dev。
- 手动值与自动值相同，或手动设置被更高优先级设置遮住时，仍能移除该设置；预览会保留来源变化，完全相同时说明结果不变。
- 恢复成功后该选项从列表移除。预览不写入配置；配置、目录版本变化后必须重新检查预览。

## 是否需要新的压缩配置

不需要增加另一套配置。现有模型、中转、全局三层压缩策略已经支持百分比、固定 token 阈值和交由客户端管理，优先级依次从模型到全局。

恢复上下文会重算百分比阈值；恢复上下文不会同时移除独立的固定压缩阈值。预览始终展示与上下文有关的压缩策略和 Codex 总量模式阈值，即使其中一项没有改变。

以下示例假设没有单独的输入上限，也没有更高优先级压缩策略：

| 上下文设置 | 压缩策略 | 策略计算阈值 | Codex 总量模式阈值 |
| --- | --- | --- | --- |
| 手动 272,000 | 90% | 244,800 | 244,800 |
| 恢复目录 1,050,000 | 90% | 945,000 | 945,000 |
| 手动 272,000 | 固定 200,000 | 200,000 | 200,000 |
| 恢复目录 1,050,000 | 固定 200,000 | 200,000 | 200,000 |
| 手动 272,000 | 固定 250,000 | 250,000 | 244,800 |

272K 快捷覆盖值、自动目录默认值与既有注入行为均保持原样。目录记录是模型能力；Codex 官方账号提供的客户端默认窗口是另一份配置来源，不能把两者强制合并为一个值。

## Codex 实现核对

官方配置支持 `model_context_window`、`model_auto_compact_token_limit` 和 `model_catalog_json`，并将压缩计量方式区分为默认 `total` 和 `body_after_prefix`。[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

核对本地官方源码副本 `D:/workspace/temp/openai-codex-source` 的提交 `aa38089`：

- `codex-rs/protocol/src/openai_models.rs` 的 `ModelInfo::auto_compact_token_limit()`：默认值为窗口的 90%；显式值与该上限取最小值。
- `codex-rs/core/src/session/context_window.rs`：`total` 使用上述模型阈值；`body_after_prefix` 的显式配置计量的是压缩前缀之后的增长，不能当作相同的总量规则。
- Codex CLI 与 Desktop 的 app-server 使用共享核心。界面的“Codex 自动压缩（总量模式）”因此是针对默认模式的配置推导，不是读取正在运行的 Desktop 会话。

路由模式仍将模型阈值写到每个模型的 `auto_compact_token_limit`。原生模式仍使用共享阈值，并受共享上下文上限约束。显示这两个模式的结果不会改变通用压缩策略，也不会改变其它客户端配置。
