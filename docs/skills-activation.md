# Codex / Claude Code Skills 启用与禁用

参考 CC Switch 的 [Skills 禁用机制](../../temp/cc-switch/docs/user-manual/zh/3-extensions/3.3.1-skills-disable-mechanism.md)，采用其核心规则：让客户端扫描不到技能，同时保留完整文件。启停操作与卸载分开。

## 当前实现范围

Skills 页可以在 Codex 和 Claude Code 之间切换，分别管理两者的用户级技能目录。原有导入、备份、移除和恢复接口保留，未传来源时仍使用 Codex。已有目录无需批量迁移；用户首次关闭开关时才移动对应技能。

| 来源 | 扫描根 | 管理存储 |
| --- | --- | --- |
| Codex | `CodexPaths.skills_dir` | 原有 `<app data>` |
| Claude Code | `CLAUDE_CONFIG_DIR/skills`，未设置时 `~/.claude/skills` | `<app data>/skill-clients/claude-code` |

以下表中的 `<client skills>` 和 `<source data>` 分别指选定来源的扫描根和管理存储。测试设置 `AGENT_HARBOR_CLIENT_HOME` 时，Claude Code 改为隔离根下的 `.claude/skills`，不会读取真实目录。

| 状态 | 文件位置 | 列表行为 |
| --- | --- | --- |
| 启用 | `<client skills>/<relativePath>` | 开关开启 |
| 禁用 | `<source data>/disabled-skills/<relativePath>` | 保留卡片，开关关闭 |
| 冲突 | 两处同时存在同一相对路径 | 标记目录冲突，提供两份目录入口和保留副本操作 |

状态每次扫描从实际位置推导，不另外保存布尔值。禁用保留 `SKILL.md`、脚本、引用文件、隐藏文件及嵌套路径；不会产生新的卸载备份。卡片的“打开文件夹”指向当前实际目录，可直接编辑禁用中的技能。

CC Switch 采用常驻主副本和多个客户端投影。本项目沿用两个互斥位置保存完整目录，每个来源的禁用目录、备份和锁互相隔离，不迁移成共享主副本。不会修改共享 `.agents/skills`、Claude 插件目录或项目级 Skills。同名技能若存在于这些其他来源，本开关不会将它全局禁用。

Claude Code 中由 CC Switch 等工具投影的符号链接和 Windows junction 显示为“外部管理”，可打开文件夹，但不能切换、移除或解冲突。本模块只读取链接目录中的直接 `SKILL.md`，不递归扫描其目标。单个链接目标不可读时单独告警，其余技能仍可使用。Codex 保持原来跳过链接的扫描行为。技能内部包含链接时，切换会报错并保留原目录。

已运行的会话可能保留技能缓存；目录变化影响客户端后续扫描，不会撤销当前会话已经载入的指令。

## 操作语义

- 新导入：默认启用。
- 替换已禁用的技能：保持禁用，旧内容照常备份。
- 对现存技能恢复备份：保持当前启停状态。
- 移除：对启用或禁用目录创建完整备份，再删除对应目录。
- 从备份恢复已移除的技能：安装到当前来源的技能目录，默认启用。
- 冲突：卡片提供“打开启用副本 / 打开禁用副本”入口；选择“保留启用副本”或“保留禁用副本”并确认，另一份完整备份后撤下。冲突状态不显示有歧义的启用开关。

单个非 UTF-8 的 `SKILL.md` 或损坏/不可读的备份 `metadata.json` 不阻止其他条目展示；列表上方单独报告被跳过的目录，并可点击打开核对，原文件不删除。扫描根或目录权限错误仍报告整体失败，避免把不可读目录误判为空。扫描期间已消失的条目可跳过。

导入覆盖、移除、恢复覆盖和解冲突在备份完成后失败时，错误中保留恢复备份 ID 与路径；备份列表会在操作失败后同样刷新。确认键在技能操作及其后续列表刷新未完成时禁用。

## 文件操作与边界

每个来源的启停、导入、移除、恢复、删除备份操作共用 `<source data>/skills.lock` 文件锁，覆盖同进程与跨进程并发。读取合并列表也使用同一把锁，避免看到本工具写入过程中的中间状态。写入完成及列表刷新结束前不能切换来源；切换后重新建立列表、搜索和确认对话框，迟到的读取结果只进入原来源的缓存。

同磁盘切换优先使用目录重命名。跨磁盘或重命名失败时，先复制到隐藏暂存目录，发布完整目标后再撤走源目录。若撤走源目录失败则回收新副本，保留原目录；如果异常中断留下双份，列表报告冲突，阻止自动覆盖。清理隐藏旧副本失败不会删除已发布的完整目录。

校验范围包括路径穿越、绝对路径、扫描根与禁用存储重叠、路径组件中的链接、隐藏技能目录，以及会把嵌套技能藏在父技能下的目标路径。禁用存储必须位于客户端扫描根之外；Claude Code 根与 Codex 扫描根、禁用目录和备份目录重叠时拒绝操作。

## 验证

临时目录测试覆盖：启停往返、嵌套与隐藏文件、重新导入、恢复、移除、同名冲突、并发切换、双来源同名技能和备份隔离、Claude Code 链接只读及扫描边界、Windows junction、复制式迁移与撤源失败。复制式迁移分支直接调用验证，不依赖测试机器拥有两个磁盘。

浏览器测试覆盖：写入期间保持旧开关状态、失败不误报成功、禁用卡片不消失、冲突开关不可操作，以及 1200/390 像素布局。均使用模拟数据，不修改真实技能。

运行：`pnpm test:rust`、`pnpm test:frontend`、`pnpm build`。单独检查界面可设置 `FRONTEND_QA_SCOPE=skills` 后运行 `node scripts/test-frontend-regressions.mjs`。
