# 线程 JSONL 可视化与优化核验（2026-09-30）

## 实现范围

- 点击线程标题进入只读详情侧栏，不改变复选框/整行的批量选择行为。
- 用量、工具、元数据、对话四个标签；Token 四项分解、按日期累计与历史模型归属。
- 对话按记录顺序每页最多 50 条，长消息可折叠；单条仅预览前 20,000 字符，完整记录仍通过原导出/原文件定位入口查看。
- 缓存输入包含于总输入，推理输出包含于总输出；仅在分项完整且一致时绘制占比。缺字段显示未知，没有有效记录不等于 0。
- 累计快照以增量统计，重复快照不重复计费；没有累计值时才用单次用量。计数回退明确提示可能重复，不把本地统计当作官方账单。
- 模型由日志 `turn_context`、`thread_settings_applied` 或用量记录确定，缺来源归为未知，不拿目录的当前模型覆盖历史。
- 保留可读工具调用、结果、推理/压缩摘要；不展示加密载荷，也不声称解密或跨模型兼容已验证。

## 参考与边界

- 参考 cc-switch `SessionManagerPage.tsx` / `SessionMessageItem.tsx` 的按需加载、角色区分与长消息折叠；参考 Magpie `internal/sessions/codex.go` 的累计用量、模型变更记录与缓存口径。
- 没有复制两项目源码，也没有引入另一套会话数据库、网关、消息渲染框架或统计索引。复用本项目的稳定 key、消息解析/去重、Sheet、导出和删除流程。
- IPC 不接受任意 `filePath`。路径只能来自所选目标的 sessions/archived 根目录；拒绝路径穿越、链接、非 rollout 文件和最终会话 ID 不匹配。
- 与列表共用 `session_id` 优先于 `id` 的解析。真实旧历史同时包含两个字段，初次探针确实发现了优先级不一致；修复后回归通过。
- Fork 文件可能包含祖先元数据；扫描到文件最后一个会话元数据再校验身份，即使第一页已满也不提前返回。继承历史明确提示。
- 每次读取冻结文件字节长度；文件追加可通过刷新更新，文件缩短则拒绝。最大文件 512 MiB、单行 8 MiB；超长行跳过并提示，正文不随线程列表进入前端。
- 消息去重复用现有跨格式配对逻辑，详情只保留最近 512 条指纹；非常远距离的重复记录仍可能显示。列表/导出的指纹改为 SHA-256，不再保存每条长消息的第二份全文。
- 详情统计和每页对话均做线性文件读取，不建立额外缓存/索引；超大历史的首次打开/翻页速度仍是后续优化点。
