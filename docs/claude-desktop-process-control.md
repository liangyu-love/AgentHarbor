# Claude Desktop 配置保存与进程控制

更新：2026-10-07。适用：直连/路由配置保存、官方切换、路由退出恢复与 Desktop 重启。

## 当前操作顺序

- 选择、检测、预览和普通配置提交均可在 Desktop 运行时进行，保存配置不会自动停止或重启应用。写入继续经过一次性预览票据、重读比对、跨进程写锁、持久 journal 与回读确认；预览后文件已变化时重新预览。
- 保存后显示“需要重启”。点击显式重启时，先确认选定安装完全退出，再读取退出时写回的最新配置，只补回两个 config 中记录的 `deploymentMode`，最后启动应用。模式补回复用备份、journal 与事务提交，不整体覆盖最新的 MCP、偏好等其它字段，也不重写外部 profile 或选择指针。
- 自身 profile 或 metadata 所有权已被外部修改时，模式补回拒绝执行；停止、补回或启动失败都保留待重启标记。只有停止与启动均确认成功，才清除“需要重启”。应用已关闭时，同一按钮负责启动已确认安装；没有管理记录也不影响这一入口。
- 未配置中转时也可以切换官方模式。该路径只把两处 `deploymentMode` 设为 `1p`，保留全部外部 metadata、profile 与企业策略；已受管会话仍按已有所有权规则撤回自己的配置。
- 未完成事务的 rollback 恢复和路由退出恢复继续要求确认 Desktop 已停止。配置保存的调整不放宽这些恢复保护；存在 pending journal 时不能直接重启或开始新写入。

Desktop 与其它配置工具不遵守 AgentHarbor 的写锁。运行中保存可能遇到 Desktop 自身回写，所以重读、冲突检查与重启后的窄模式补回都保留；它们不提供跨工具任意并发写入的绝对保证。

## 既有耗时优化

原先每次停止检查都重新查询 MSIX 安装信息并启动 `tasklist`；一次四文件事务会做多次检查。轮询停止和启动也反复启动外部程序。部分辅助命令没有超时，`taskkill` 的失败状态没有检查；枚举后恰好退出的进程被误判为无法确认身份。

- Windows 改用 ToolHelp 枚举、查询进程映像和退出状态，不再调用 `tasklist` / `taskkill`。
- 需要确认停止的恢复与模式补回检查复用已发现的安装身份，并核对实时进程状态，不缓存“已停止”。普通配置提交不再用运行状态阻止保存。
- 重启在停止后重新发现安装身份，兼容自动更新更换可执行文件。退出恢复的前后停止检查共用已确认的安装身份。
- 正常关闭使用异步 `WM_CLOSE`，挂起窗口不会阻塞调用。没有窗口时最多等待约 2 秒供 Electron 建窗，然后进入残留处理；已成功投递关闭请求或投递报错的进程保留正常退出预算。
- 强制终止前，在同一个进程句柄上核对可执行文件；只处理选中的 Desktop 安装，不终止子进程或 Claude Code 工具。
- 已退出候选进程被忽略；访问失败、枚举失败和身份未知仍不能作为成功停止的证据。
- MSIX 安装发现辅助命令限时 10 秒，macOS 发现限时 5 秒，Unix `pgrep` / `ps` / `kill` 限时 2 秒，并检查退出码。发现失败保留重启按钮供重试，真正未安装或隔离根不提供重启。
- 辅助命令输出写入临时文件，避免管道阻塞；输出限额 1 MiB。超时或读取失败终止子进程，回收最多等待 500 ms，必要时在后台继续回收。

显式重启遵守“先停 Desktop → 补回已保存模式 → 启动”，普通配置保存不包含停止阶段。重启的正常退出等待上限仍为 20 秒，退出路由恢复为 10 秒；强制退出确认上限 5 秒，启动确认上限 25 秒。安装发现与辅助命令清理耗时另外计算，这些上限不是整个操作的总预算。

信号失败记录 PID、阶段及原因，但不跳过其余已确认进程。强制阶段无法枚举或确认停止时返回 `processStopTimeout` 和手动退出指引；失败的查询不能授权依赖停止确认的恢复与模式补回。
