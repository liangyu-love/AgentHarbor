# Claude Desktop 恢复与重启耗时修复记录

日期：2026-10-05。适用：直连配置提交、路由退出恢复、Desktop 重启。

## 原因与改动

原先每次停止检查都重新查询 MSIX 安装信息并启动 `tasklist`；一次四文件事务会做多次检查。轮询停止和启动也反复启动外部程序。部分辅助命令没有超时，`taskkill` 的失败状态没有检查；枚举后恰好退出的进程被误判为无法确认身份。

- Windows 改用 ToolHelp 枚举、查询进程映像和退出状态，不再调用 `tasklist` / `taskkill`。
- 配置事务只发现一次安装身份；每个文件写入前、状态提交前仍重新读取实时进程列表，不缓存“已停止”。
- 重启共用同一安装身份进行停止和启动。退出恢复的前后停止检查共用安装身份。
- 正常关闭使用异步 `WM_CLOSE`，挂起窗口不会阻塞调用。没有窗口接收关闭请求时，立即检查并处理残留进程，避免空等正常退出期限。
- 强制终止前，在同一个进程句柄上核对可执行文件；只处理选中的 Desktop 安装，不终止子进程或 Claude Code 工具。
- 已退出候选进程被忽略；访问失败、枚举失败和身份未知仍拒绝配置写入。
- MSIX / macOS 安装发现辅助命令限时 5 秒，Unix `pgrep` / `ps` / `kill` 限时 2 秒，并检查退出码。
- 辅助命令输出写入临时文件，避免管道阻塞；输出限额 1 MiB。超时或读取失败终止子进程，回收最多等待 500 ms，必要时在后台继续回收。

仍遵守“先停 Desktop，再写配置，最后启动”。重启的正常退出等待上限仍为 20 秒，退出路由恢复为 10 秒；强制退出确认上限 5 秒，启动确认上限 25 秒。安装发现与辅助命令清理耗时另外计算，这些上限不是整个操作的总预算。

## 验证

- `pnpm test:rust`：797 项单元测试、11 项 Desktop 工作流、15 项本地工作流通过；真实配置/联网等显式运行用例未执行。
- `FRONTEND_QA_SCOPE=claude-desktop-card pnpm test:frontend`：Desktop 配置静态检查 10 组及对应浏览器回归通过。
- 测试自建隐藏窗口和无窗口子进程，覆盖异步关闭、残留处理、错误身份不终止、已退出进程、PID 0、辅助程序超时回收与失败退出码。
- 保留并通过每文件写入前及状态提交前实时停止检查的断言。
- 最后清理分支修正后重跑进程控制测试：19 项通过，1 项子进程夹具不单独运行。
- 本机两次只读测量：安装发现分别为 837 / 467 ms；随后十轮原生枚举与停止检查分别共 309 / 313 ms。此前暖启动 MSIX 发现约 364–444 ms，`tasklist` 约 423–556 ms，单轮检查重复承担两者开销。测量环境与轮次不同，仅用于说明检测开销；不代表完整重启耗时。

本轮没有停止或重启真实 Desktop，没有改写真实配置。Windows 原生进程控制已通过上述测试；macOS / Linux 辅助命令限时改动未在对应真机验证。Desktop 自身退出、配置回写及启动速度仍影响用户看到的完整耗时。
