# models.dev model metadata

AgentHarbor resolves model capabilities and prices through one resolver fed by
the [models.dev](https://github.com/anomalyco/models.dev) catalog. This document
describes where the data comes from, how a value is chosen, and what is never
derived from a model's name.

## Data sources

| Source | Where it lives | Notes |
| --- | --- | --- |
| Bundled snapshot | `src-tauri/assets/models-dev.snapshot.json` | Committed, generated by `node scripts/build-models-dev-snapshot.mjs`; used offline and as the last resort. |
| Runtime cache | `<app data>/models-dev.json` | Written atomically after a successful download; always wins over the bundled snapshot when it is whole and valid. Never merged with it. |
| Refresh | `load_models_dev_status` / `refresh_models_dev_catalog` commands and an hourly background check | 24-hour validity, conditional `If-None-Match` requests, failures keep the last valid catalog and report `lastRefreshError`. |

Update the bundled snapshot explicitly for a release. Normal builds only read
the committed file and never require network access.

## Matching

`model_metadata::candidates` turns a configured model ID into an ordered list of
candidate identities, recording every step (`pathPrefix`, `channelMarker`,
`knownChannelSuffix`, `effortSuffix`, `tagSuffix`, Bedrock `regionPrefix`, …).
Versions, dates and `-preview` suffixes are never removed. Matching kinds:

- `explicit` – a user-bound `{providerId, modelId}`; a stale binding fails closed.
- `exact` / `normalized` – a scoped match inside the provider's configured
  capability catalogs (`catalogProviders`).
- `consensus` – a generic reference across the whole catalog; only fields that
  agree everywhere are filled in, listed as `catalogGeneric`.
- `ambiguous` – same-priority candidates disagree; agreeing fields are kept and
  the rest are reported as conflicts instead of guessed.
- `unmatched` – nothing matched; clients see the shared fallback, marked as such.

Prices are always scoped to the billing provider (`priceCatalogProvider`, else
the capability mapping, else the model's `priceRef`). They are never averaged or
borrowed across providers, and `:free`/`@fast`-style tags never borrow the base
model's price.

## Field precedence

For every field the resolver reads, in order:

1. Explicit user overrides (`overrides.*`).
2. Provider-level settings (`contextWindow`).
3. Real upstream declarations collected from the provider's model list.
4. The signed-in Codex account snapshot, and only when the provider targets the
   official endpoint.
5. models.dev exact/normalized match.
6. Unambiguous generic reference.
7. The shared fallback (`128 000` / `8 192`), clearly labelled `fallback`.

Compression thresholds follow `model → provider → global` inheritance with a
default of 90% of the effective prompt budget (`limit.input` when the catalog
provides it, otherwise `limit.context`). Fixed token thresholds never move on a
catalog refresh; percentages are recomputed.

| Field | Coverage | Use |
| --- | --- | --- |
| `limit.context` / `limit.output` | 8339 / 8339 (100%) | Effective window and output cap. |
| `limit.input` | 1441 (17%) | Preferred compression budget when present. |
| `reasoning_options` | 6148 (74%) — effort 3829, toggle 1384, budget_tokens 598 | Reasoning levels and raw capabilities. |
| `cost` | 7915 (95%) — `cache_read` 5368, `cache_write` 1790, `reasoning` 152, `tiers` 614, `context_over_200k` 519 | Estimated pricing. |
| `modalities` | 8339 (100%) | Input/output modality list. |
| `canonical_model_id` | 5274 (63%) | Kept for reference; identity matching does not depend on it. |
| `status` | 324 | Deprecation marker, shown in the catalog view. |

`budget_tokens.min` uses `-1` upstream for "unset"; the snapshot drops it and
the deserializer treats non-positive values as missing.

The snapshot keeps limits, reasoning options, the full cost structure
(including tiers and `context_over_200k`), modalities, status, dates and
`canonical_model_id`. Descriptions, logos and benchmarks are dropped.

## Migration

Store schema v8 introduces `overrides`, `catalogRef`, `priceRef` and
`compression`. The one-time migration:

- moves `metadata_source = "manual"` values into `overrides`,
- demotes historical `upstream` values to `legacy` (they may have been
  overwritten by the removed local defaults),
- clears auto-filled `local`/`catalog` limits so the resolver re-derives them,
- converts a non-empty `autoCompactLimit` into a provider `tokens` policy.

Back up `<app data>/newapi-providers.dat` before a downgrade; user IDs,
protocols, aliases and overrides are never cleared by the migration.
